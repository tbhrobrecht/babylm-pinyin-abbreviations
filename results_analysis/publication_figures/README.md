# Publication figures

This directory contains the reproducible figure generator for the Mandarin
BabyLM model comparison. It reads the generated tables in
`results_analysis/processed/` and writes numbered figures to `output/`. PDF and
SVG are generated by default; 600-DPI PNG is available on request.

Two generators are provided:

- `generate_figures.py` creates comprehensive figures for supplementary or
  appendix use.
- `generate_main_figures.py` creates compact, conclusion-oriented figures for
  the main paper and writes them to `main_body_output/`.

## Generate all figures

From the repository root:

```bash
uv venv /tmp/babylm-figures-venv
UV_CACHE_DIR=/tmp/babylm-uv-cache uv pip install \
  --python /tmp/babylm-figures-venv/bin/python \
  -r results_analysis/publication_figures/requirements.txt
/tmp/babylm-figures-venv/bin/python \
  results_analysis/publication_figures/generate_figures.py

/tmp/babylm-figures-venv/bin/python \
  results_analysis/publication_figures/generate_main_figures.py
```

To additionally render 600-DPI raster copies, append
`--formats pdf svg png`. The temporary environment keeps plotting dependencies
outside the LRZ home quota.

The generator validates that every registered model occurs in every primary
metric before drawing anything. Run `results_analysis/build_results_summary.py`
first whenever evaluation data or the model registry changes.

## Integrating future evaluations

The plotting code does not contain a list of model names. Model ordering,
architecture, tokenizer, scale, and cohort are read from
`results_analysis/models.json`; scores and contrasts are read from the processed
tables. To add another completed evaluation cohort:

1. Copy its raw evaluation directories into the repository's artifact layout.
2. Add one entry per completed model to `results_analysis/models.json`, using
   tokenizer values `Atomic BPE within` or `Atomic BPE cross` and scale `100M`.
3. Rebuild the processed tables:

   ```bash
   python results_analysis/build_results_summary.py
   ```

4. Validate the plotting inputs without rendering:

   ```bash
   /tmp/babylm-figures-venv/bin/python \
     results_analysis/publication_figures/generate_figures.py --validate-only
   ```

5. Regenerate all figures with the command above, or update only selected
   families, for example:

   ```bash
   /tmp/babylm-figures-venv/bin/python \
     results_analysis/publication_figures/generate_figures.py \
     --figures task_heatmap paired_effects within_cross suite_averages cogbench_regions
   ```

The within/cross generator discovers complete `(scale, architecture)` pairs and
creates one page per scale. It raises a clear validation error if only one side
of a within/cross pair is registered. Figure dimensions and scale-marker legends
expand automatically as models are added. The summary builder also discovers
valid scale, tokenizer, boundary-policy, and architecture contrasts from the
registry, so completed 100M atomic models automatically enter the paired-effect
forest plot.

The main-text generator uses the same registry, input validation, visual style,
and export functions as the supplementary generator. Its available figure keys
are `overview`, `scaling`, `boundaries`, and `task_profiles`; use `--figures`
to render any subset. Scaling lines are shown only for conditions available at
two or more scales, and boundary lines are shown only for complete within/cross
pairs. This prevents lines from silently connecting unmatched models.

## Figures

### Main-text figures

1. `M1_experimental_overview`: compact pipeline from training data through
   evaluation and matched contrasts.
2. `M2_scaling_trajectories`: suite-level trajectories over model scale for
   matched architecture–tokenizer conditions.
3. `M3_boundary_policy_trajectories`: matched within-word to cross-word changes
   for each available scale and architecture.
4. `M4_task_family_profiles`: mean within-task percentile-rank profiles. Ranking
   within tasks makes the aggregation robust to incompatible metric units.

See `MAIN_BODY_CAPTIONS.md` for manuscript-ready draft captions and the explicit
task-family definitions.

### Supplementary figures

1. `01_task_by_model_heatmap`: raw task scores annotated over task-centered
   colors. Centering prevents easy tasks from dominating the color scale.
2. `02_paired_effect_forest`: task-level paired differences and suite means.
   Points are observed tasks, not independent model-training replicates.
3. `03_experimental_design`: evaluated and pending cells in the factorial
   size × architecture × tokenizer design.
4. `04_within_vs_cross_dumbbell_<scale>`: direct within-word/cross-word
   comparisons for every registered architecture and scale on every task.
5. `05_suite_average_dotplot`: unweighted descriptive means within each suite.
6. `06_cogbench_region_heatmap`: mean CogBench fMRI score by region and model.

## Visual conventions

- Tokenizer colors use the colorblind-safe Okabe–Ito palette.
- Architecture is encoded by point shape where applicable.
- All numeric axes show score ×100 for compact, consistent labels. CogBench
  remains correlation-based and is never combined with accuracy suites.
- PDF and SVG are the preferred manuscript formats. Optional 600-DPI PNG is
  intended for previews and submission systems that require raster artwork.
- No confidence interval is shown because there is one trained seed per model.
  The forest plot displays task dispersion without presenting it as model-level
  uncertainty.
